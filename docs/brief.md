# SilentOrchestra 2.0 프로젝트 브리프

기획 배경 문서입니다. 범위·지표·규칙은 [spec.md](../spec.md)가 소유합니다.

## 한 줄 정의

반복되는 몸짓과 실제 후속 조작, 활성 앱을 관찰해 사용자가 승인한 개인별 행동 연결을 기억하는 로컬 우선 Spatial AI Agent.

‘개인의 몸짓 언어’는 제품 방향입니다. 현재는 두 활동 안에서 제한된 동작과 이산 행동의 연관을 학습하며, 자유로운 몸짓 어휘나 문법을 학습하지 않습니다.

## 문제

기존 제스처 제어는 시스템이 미리 정한 동작을 사용자가 외우고 정확히 재현해야 합니다. 사용자의 자연스러운
습관을 반영하지 못하고, 같은 몸짓이 발표·음악처럼 상황에 따라 다른 의미를 가질 수 있다는 점을 다루지 못합니다.

## 대상 사용자

- 발표 중 키보드·리모컨에서 손을 떼고 화면을 제어하려는 사용자
- 음악 감상 중 같은 몸짓을 개인 습관대로 쓰고 싶은 사용자
- 고정된 제스처 명령 체계보다 학습되는 개인화 인터페이스가 필요한 사용자
- 카메라 기반 서비스에서 영상 저장과 얼굴 인식에 민감한 사용자

## 핵심 가치

1. **Learned action mapping** — 지원하는 몸짓의 의미를 반복된 후속 조작에서 배움
2. **App-based context** — 활성 앱으로 활동을 구분하고 같은 몸짓도 다른 의도로 해석
3. **Human approval first** — 반복 패턴을 발견해도 승인 전에는 자동 실행하지 않음
4. **Personal Gesture Memory** — AI가 사용자에 대해 배운 것을 가시화
5. **Local motion data** — 원본 프레임은 폐기하고 모션 특징만 로컬 저장; 얼굴·신원 인식은 사용하지 않음

## 차별점

```text
기존 Gesture Control
Gesture → Classifier → Command

SilentOrchestra 2.0
Observation → Context + History → Candidate Intent
→ Confidence → Suggestion/Execution → Feedback → Memory Update
```

Windows 웹캠 관측 경로는 사용자가 발표·음악 앱에서 원래 하던 키 조작을 몸짓 뒤에 연결합니다. 활동은 활성 앱으로 판정하고, 몸짓의 실측 시간·속도·진폭을 특징으로 남깁니다. 고정 특징과 최근 행동 통계를 쓰는 구현이며, 신경망이나 개인 신원 인식 모델을 학습하지 않습니다. 웹 UI와 라벨 입력 모드는 이 루프를 재현하는 시뮬레이션입니다.

## 현재 한계와 사용 비용

웹캠 어휘는 좌우 swipe 두 개, 활동은 발표·음악 두 개이며 몸짓·활동 조합마다 하나의 이산 행동만 활성화합니다. 연속량, 시퀀스, 수식어는 없습니다. 관례적인 오른쪽 손짓→다음 슬라이드만 보여주는 데모는 개인화의 효과를 입증하지 못합니다. 실제 개인차를 얼마나 구분하는지는 별도 검증이 필요합니다.

처음에는 반복 관찰과 승인에 비용이 들고, 승인 전에는 자동 실행하지 않습니다. 초기 학습과 재학습은 발표 리허설에서 기존 조작과 함께 수행하는 흐름입니다. 승인·수정·피드백은 수동이므로 전체 사용 과정이 hands-free인 제품으로 소개하지 않습니다. 단일 매핑을 빠르게 만드는 데에는 직접 설정이 더 간단할 수 있습니다.

## 기술 선택

FastAPI · SQLite + SQLAlchemy · Vanilla HTML/CSS/JS · 선택적 OpenCV Optical Flow ·
Pytest + FastAPI TestClient. 전부 local-first이며 원본 프레임은 폐기합니다.
선택 근거는 [decision-log.md](decision-log.md).
