# 예상 질문과 답변

## Q1. 단순 제스처 분류와 무엇이 다른가요?

분류 모델의 출력이 곧 명령이 되지 않습니다. 제스처 특징, 현재 Context, 개인의 이전 행동, 승인된 Memory를 함께 보고 Intent를 추론합니다. 반복 패턴은 먼저 제안하고 승인 후에만 자동 실행합니다.

## Q2. 세 번만 반복하면 오작동하지 않나요?

세 번은 해커톤 데모를 위한 최소 임계값입니다. 실제 제품에서는 맥락별 일관성, 시간 간격, 부정 피드백, 오작동 비용에 따라 동적으로 조정해야 합니다. confidence가 낮으면 자동 실행하지 않습니다.

## Q3. 카메라 개인정보 문제는 어떻게 해결했나요?

원본 프레임을 DB나 파일로 저장하지 않습니다. Optical Flow 계산은 메모리에서 수행하고, 모션 특징 벡터만 로컬에 남깁니다. 얼굴 인식과 클라우드 영상 업로드도 사용하지 않습니다.

## Q4. 같은 몸짓이 여러 행동과 연결되면 어떻게 하나요?

Context scope별 기억을 분리하고, 같은 Context에서는 가장 많이 관찰된 후속 행동 하나를 승격 후보로 삼습니다. 최빈 행동이 동률이면 해당 몸짓·맥락의 활성 기억을 후보 상태로 내리고 자동 실행을 끄며 대기 제안을 삭제합니다. 추론 점수가 자동 실행 임계값 미만이어도 실행하지 않습니다. 자세한 규칙은 [SPEC L-3~L-6](../spec.md#맥락학습-fr-02-fr-04-fr-05-fr-07)과 [I-3](../spec.md#추론실행-fr-06-fr-10-fr-11)을 따릅니다.

## Q5. 왜 LLM을 쓰지 않았나요?

MVP의 핵심은 개인 행동 학습 루프와 안전한 실행입니다. LLM은 이유 설명이나 범용 Intent 확장에 붙일 수 있지만, 현재 범위에서는 규칙 기반 confidence가 더 재현 가능하고 데모 안정성이 높습니다.

## Q6. 실제 PowerPoint가 움직이나요?

기본값은 DRY_RUN으로 안전하게 결과를 보여줍니다. [운영 가이드](operations.md)에 따라 OS 실행을 활성화하고 대상 앱의 활성 창 확인을 통과하면 실제 키 입력을 보낼 수 있습니다. 발표 현장 안정성을 위해 기본 데모는 시뮬레이션입니다.

## Q7. 데이터셋이 필요한가요?

개인화 서비스이므로 대규모 외부 데이터셋보다 사용자의 반복 관찰 데이터가 핵심입니다. MVP는 합성·실시간 이벤트로 동작하며, 원본 영상 데이터셋을 보관하지 않습니다.

## Q8. 확장 가능성은 무엇인가요?

미디어 제어 외에 IoT, 타이머, 접근성 보조, 스마트홈, AR 인터페이스로 확장할 수 있습니다. 새로운 Action Executor를 추가하되 Observation-Memory-Feedback 구조는 유지할 수 있습니다.
