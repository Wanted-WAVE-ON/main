# 예상 질문과 답변

## Q1. 단순 제스처 분류와 무엇이 다른가요?

분류 결과에 명령을 미리 고정하지 않고, 몸짓 뒤의 조작을 활동별로 집계해 승인된 기억을 만듭니다. 실측 입력에서는 시간·속도·진폭의 유사도도 실행 판단에 반영합니다. 현재는 고정 특징과 통계 기반 개인화이며, 자유로운 몸짓이나 신경망 모델을 학습하는 시스템은 아닙니다.

## Q2. 세 번만 반복하면 오작동하지 않나요?

세 번은 해커톤 데모를 위한 최소 임계값입니다. 실제 제품에서는 맥락별 일관성, 시간 간격, 부정 피드백, 오작동 비용에 따라 동적으로 조정해야 합니다. confidence가 낮으면 자동 실행하지 않습니다.

## Q3. 카메라 개인정보 문제는 어떻게 해결했나요?

원본 프레임을 DB나 파일로 저장하지 않습니다. Optical Flow 계산은 메모리에서 수행하고, 모션 특징과 활동·행동 기록만 로컬에 남깁니다. 얼굴 인식과 클라우드 영상 업로드도 사용하지 않습니다. 이는 데이터 처리 범위를 제한하는 설계 선택이며 얼굴 인식을 쓰지 않는다는 사실만으로 개인화 성능을 주장하지 않습니다. 실제 입력 관측도 허용된 제어 키만 행동으로 바꾸며 일반 입력 문자열은 저장하지 않습니다.

## Q4. 같은 몸짓이 여러 행동과 연결되면 어떻게 하나요?

활동별로 최근 행동의 최빈값 하나를 후보로 삼습니다. 동률이 되거나 다른 행동이 새 승자가 되면 기존 활성 기억의 자동 실행을 끕니다. 최근성·거절 후 재제안 조건은 [SPEC L-3~L-6, M-5](../spec.md#맥락학습-fr-02-fr-04-fr-05-fr-07)를 따릅니다. 추론 시에도 유사도가 낮거나 서로 다른 의도의 점수가 비슷하면 실행을 보류합니다. 습관을 바꿀 때는 [학습 모드](operations.md#웹캠-학습과-실제-조작-관측)로 자동 실행을 끄고 새 후속 조작을 관측할 수 있습니다.

## Q5. 왜 LLM을 쓰지 않았나요?

MVP의 핵심은 개인 행동 학습 루프와 안전한 실행입니다. LLM은 이유 설명이나 범용 Intent 확장에 붙일 수 있지만, 현재 범위에서는 규칙 기반 confidence가 더 재현 가능하고 데모 안정성이 높습니다.

## Q6. 실제 PowerPoint가 움직이나요?

기본값은 DRY_RUN으로 안전하게 결과를 보여줍니다. [운영 가이드](operations.md)에 따라 OS 실행을 활성화하고 대상 앱의 활성 창 확인을 통과하면 실제 키 입력을 보낼 수 있습니다. 발표 현장 안정성을 위해 기본 데모는 시뮬레이션입니다.

## Q7. 데이터셋이 필요한가요?

개인화 서비스이므로 대규모 외부 데이터셋보다 사용자의 반복 관찰 데이터가 핵심입니다. MVP는 합성·실시간 이벤트로 동작하며, 원본 영상 데이터셋을 보관하지 않습니다.

## Q8. 확장 가능성은 무엇인가요?

미디어 제어 외에 IoT, 타이머, 접근성 보조 등을 검토할 수 있습니다. 현재 웹캠은 좌우 swipe와 발표·음악 두 활동에 한정됩니다. 몸짓·활동당 하나의 이산 행동만 기억하므로 연속량이나 시퀀스를 다루려면 관찰·기억 모델도 확장해야 합니다.

## Q9. 행동을 직접 골라야 한다면 학습이 아니라 라벨링 아닌가요?

웹 UI의 드롭다운과 기존 웹캠의 N/B/Space 입력은 맞습니다. 실제 앱을 조작하지 않고 `/teach`에 행동을 전달하던 라벨 시뮬레이션이며, 이를 자연스러운 행동 관측이라고 소개하면 부정확합니다.

Windows 관측 모드는 지원 앱에서 사용자가 실제로 누르는 탐색·미디어 키를 관측합니다. 몸짓 직후 같은 앱에서 발생한 첫 조작만 연결하고, 자동 실행이 만든 합성 키는 제외합니다. 별도 라벨 선택을 줄였지만, 몸짓을 반복하고 최초 제안을 승인하는 비용은 남습니다. 다른 OS의 라벨 모드는 실기 관측과 구분해 안내합니다. 절차와 키 범위는 [운영 가이드](operations.md#웹캠-학습과-실제-조작-관측)에 있습니다.

## Q10. 맥락 버튼을 누를 수 있다면 행동 버튼을 누르면 되지 않나요?

실기 기본 경로는 활성 앱으로 발표·음악 맥락을 판정합니다. 관찰 요청에서 activity를 생략하면 전달된 active_app을 사용하고, 앱도 없으면 서버의 활성 창을 읽습니다. 지원하지 않거나 두 활동으로 모호하게 매칭되는 앱은 관찰을 거부합니다. UI의 맥락 버튼과 CLI의 명시적 activity는 시뮬레이션·수동 override이며, 공간·기기 정보는 저장만 하는 메타데이터입니다. 방 전체나 사용자의 목적을 이해하는 맥락 추론은 아닙니다.

## Q11. 학습 중에도 hands-free인가요? 처음부터 직접 설정하면 더 빠르지 않나요?

초기 학습·승인·피드백까지 hands-free는 아닙니다. 리허설에서 기존 조작을 관측하고 승인한 뒤, 실행 단계에서 키보드 사용을 줄이는 흐름입니다. 승인 전에는 자동 실행하지 않으므로 콜드스타트 비용이 있습니다. 한 개 매핑만 빠르게 만들 목적이라면 직접 설정이 더 간단할 수 있고, 반복 사용에 따른 편익은 아직 실사용으로 검증해야 합니다.

## Q12. 같은 swipe라도 개인차를 배우나요?

웹캠에서 실제 지속 시간·ROI 기준 속도·진폭을 남기므로 같은 방향도 다른 특징 벡터가 될 수 있습니다. 최근 같은 행동에 연결된 관찰의 평균과 비교합니다. 키 일치만으로 실행을 결정하지 않지만 고정 인코더이며, 궤적 전체나 신원을 학습하지 않습니다. 기존 시뮬레이션 기억과 실측 기억은 특징 차원이 달라 서로 매칭하지 않으므로 실측 경로에서 다시 학습해야 합니다. 개인차 분류 성능은 하드웨어 검증 전입니다.

## Q13. 거절하거나 무심코 움직였을 때도 같은 제안이 계속 나오나요?

거절한 행동은 거절 이후의 새 증거가 충분히 쌓여야 다시 제안합니다. 무의식적 몸짓 피드백은 올바른 행동 매핑의 신뢰도를 깎지 않고 유사 모션의 실행을 잠시 억제합니다. 이는 임시 보호이며 제스처 감지 모델을 재학습하는 기능은 아닙니다. 수치와 적용 범위는 [SPEC M-5](../spec.md#승인기억-fr-08-fr-09), [F-2](../spec.md#피드백-fr-12-fr-13)를 따릅니다.
