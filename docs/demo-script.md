# 3분 해커톤 데모 대본

## 준비

[README 시작하기](../README.md#시작하기)에 따라 로컬 데모를 연 뒤 `Reset demo`를 누르고 Context가 `Presentation`인지 확인한다. 실제 OS 키 입력은 끈 상태로 유지한다.

이 대본은 **버튼·라벨 시뮬레이션**이다. 시작할 때 이를 밝힌다. 실기 입력을 보여줄 경우에는 [운영 가이드](operations.md#웹캠-학습과-실제-조작-관측)를 따르고, 실제 키 관측·활성 앱 판정과 아래 수동 조작을 혼동해 설명하지 않는다.

## 타임라인

### 0:00–0:25 · 문제와 관점

> "SilentOrchestra는 몸짓 뒤의 반복 행동을 활동별로 기억합니다. 지금은 버튼으로 학습 루프를
> 재현하는 시뮬레이션이며, 행동과 맥락을 직접 선택합니다."

### 0:25–1:10 · 학습 과정

`오른쪽 손짓` → **아무 자동 실행도 없음을 강조** → 후속 행동 `다음 슬라이드` 선택. 총 3회 반복.

> "처음에는 자동 실행하지 않습니다. 여기서는 다음 슬라이드를 라벨로 고릅니다. Windows 실기 경로는
> 같은 앱에서 실제로 누른 조작을 관측해 이 자리를 채웁니다."

### 1:10–1:35 · Agent 제안

오른쪽 패널에 "이 몸짓을 '다음 슬라이드'로 기억할까요?" → `기억하기` 클릭.

> "반복 패턴을 발견해도 자동 등록하지 않습니다. 사용자 승인을 받은 뒤에만 Personal Gesture Memory가
> 활성화됩니다."

### 1:35–1:55 · 자동 실행

다시 `오른쪽 손짓` → 전체 오버레이에 `다음 슬라이드 · Learned gesture · confidence`.

> "이제 같은 발표 맥락에서는 개인 기억을 검색해 다음 슬라이드 의도로 해석합니다."

### 1:55–2:30 · Context reasoning

Context를 `Music`으로 변경 → 같은 손짓을 `다음 트랙`과 3회 연결 → 제안 승인 → 자동 실행.

> "같은 손짓을 활동별로 기억합니다. 실기에서는 활성 앱으로 활동을 판정하고, 여기서는 버튼으로
> 전환합니다. 현재 범위는 발표·음악 두 활동입니다."

### 2:30–2:50 · Feedback loop

실행 오버레이에서 `맞아요` 또는 `아니에요`.

> "잘못된 행동의 피드백은 신뢰도에 반영됩니다. 초기 반복과 승인, 피드백 조작은 여전히 필요하며,
> 승인 후 실행 단계에서 키보드 사용을 줄이는 흐름입니다."

### 2:50–3:00 · Privacy

왼쪽 Privacy 카드를 지목하며 마무리.

> "원본 프레임을 저장·업로드하지 않습니다. 지원하는 동작의 반복 패턴을 개인별 기억으로 만드는
> 데모입니다."

오른쪽 손짓→다음 슬라이드는 흐름 설명용 사례이며 이 사례만으로 개인화 효과를 입증했다고 말하지 않는다. 웹캠의 좌우 swipe 어휘와 실측 특징 비교 성능은 [검증 기록](fr-17-validation.md)의 한계를 함께 설명한다.

## 실패 시 대체 흐름

| 상황 | 대응 |
|---|---|
| 웹캠 실패 | 버튼 기반 Stable Simulation으로 진행 |
| OS 키 입력 실패 | DRY_RUN 오버레이로 실행을 증명 |
| 학습 데이터가 꼬임 | `Reset demo` 후 Presentation 한 흐름만 시연 |
| 시간 부족 | Presentation까지만 시연하고 Music 분기는 Memory 화면으로 설명 |
