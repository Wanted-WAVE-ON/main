# 3분 해커톤 데모 대본

## 준비

[README 시작하기](../README.md#시작하기)에 따라 로컬 데모를 연 뒤 `Reset demo`를 누르고 Context가 `Presentation`인지 확인한다. 실제 OS 키 입력은 끈 상태로 유지한다.

## 타임라인

### 0:00–0:25 · 문제와 관점

> "기존 제스처 제어는 사용자가 시스템이 정한 손동작을 외워야 합니다. SilentOrchestra는 반대로 AI가
> 사용자의 반복 행동과 현재 상황을 관찰해 개인의 몸짓 언어를 학습합니다."

### 0:25–1:10 · 학습 과정

`오른쪽 손짓` → **아무 자동 실행도 없음을 강조** → 후속 행동 `다음 슬라이드` 선택. 총 3회 반복.

> "처음에는 몸짓을 명령으로 단정하지 않습니다. 발표 상황에서 오른쪽 손짓 직후 다음 슬라이드 행동이
> 반복되는지 관찰합니다."

### 1:10–1:35 · Agent 제안

오른쪽 패널에 "이 몸짓을 '다음 슬라이드'로 기억할까요?" → `기억하기` 클릭.

> "반복 패턴을 발견해도 자동 등록하지 않습니다. 사용자 승인을 받은 뒤에만 Personal Gesture Memory가
> 활성화됩니다."

### 1:35–1:55 · 자동 실행

다시 `오른쪽 손짓` → 전체 오버레이에 `다음 슬라이드 · Learned gesture · confidence`.

> "이제 같은 발표 맥락에서는 개인 기억을 검색해 다음 슬라이드 의도로 해석합니다."

### 1:55–2:30 · Context reasoning

Context를 `Music`으로 변경 → 같은 손짓을 `다음 트랙`과 3회 연결 → 제안 승인 → 자동 실행.

> "몸짓 자체가 명령은 아닙니다. 사용자, 제스처, 맥락이 합쳐져 Intent가 됩니다. 같은 오른쪽 손짓이
> 발표에서는 다음 슬라이드, 음악에서는 다음 트랙입니다."

### 2:30–2:50 · Feedback loop

실행 오버레이에서 `맞아요` 또는 `아니에요`.

> "실행 후 피드백은 confidence에 반영됩니다. 반복해서 틀리면 자동 실행을 중지하고 다시 학습 상태로
> 돌아갑니다."

### 2:50–3:00 · Privacy

왼쪽 Privacy 카드를 지목하며 마무리.

> "원본 영상, 얼굴 인식, 클라우드 영상 업로드는 사용하지 않습니다. Motion × Context × Personal Memory로
> 사람에게 맞춰지는 인터페이스를 만들었습니다."

## 실패 시 대체 흐름

| 상황 | 대응 |
|---|---|
| 웹캠 실패 | 버튼 기반 Stable Simulation으로 진행 |
| OS 키 입력 실패 | DRY_RUN 오버레이로 실행을 증명 |
| 학습 데이터가 꼬임 | `Reset demo` 후 Presentation 한 흐름만 시연 |
| 시간 부족 | Presentation까지만 시연하고 Music 분기는 Memory 화면으로 설명 |
